# DATA DICTIONARY — the five input tables and the twenty result tables

Generated by `make_dictionary.py`. Row counts, types, null shares and ranges are measured from the files on every run; the meaning of each column is maintained by hand in that script.

Every table here is a **derived join**, not a verbatim agency file. Each column is tagged `agency` (copied from the source record unchanged), `derived` (computed by a build script) or `key` (an identifier used to join the sources), so a reader can tell which values could carry our mistakes and which could not.

**used** marks a column some script in this project reads. *carried* marks one that is present but never read — kept because it costs nothing, flagged so nobody assumes it is part of the analysis.

Provenance and checksums for the raw inputs these were built from are in `SOURCES.md`.

## The one column excluded on purpose

`oh_analysis.csv` carries `n_q_total`, the number of quarters a well has reported. It is **not** in any feature set. It is downstream of the outcome — a well that produces more is reported for longer — and correlates +0.26 with the target. It was found during the covariate audit, removed, and every Ohio result regenerated; its removal moves the headline Ohio inflation from +0.111 to +0.118. The column is kept in the table so the audit can be repeated, and `oh_feat_audit.py` does exactly that.

## What the model actually sees

The feature vector has the same six slots in every state, but the quantity in the last two slots is whatever that regulator publishes, and the slot names in the code are historical. The mapping is:

| slot | Pennsylvania | Ohio | New Mexico | Colorado |
|---|---|---|---|---|
| `lat`, `lon` | `lat_index`, `lon_index` | `lat`, `lon` | `lat`, `lon` | `lat`, `lon` |
| `spud_year` | `spud_date` | `DT_SPUD` → `first_prod` | `spud_dte` | `spud_dte` |
| `depth` | `total_depth_ft` | `DTD` | `md` | `max_md` |
| `elev` | `elevation_ft` | `ELEV_GR` | **`tvd`** | `ground_elev` |
| `n_stim` | `n_stimulations` | *(absent — five features)* | **`n_pools`** | `max_tvd` |

**New Mexico is the serious case.** Of 13,947 wells, measured depth is zero for 39.6% and true vertical depth for 41.4% — the OCD writes a zero where no depth was filed. These enter the model as the number zero, not as a missing value, even though 
This is a defect in the feature, and it is reported here rather than left for a reader to find. It does not reach the measurement, for a reason that is structural rather than lucky: the quantity this paper reports is the **difference** between two partitions of one table. Both partitions see the same degraded column, so a degraded column cannot open a gap between them — it can only lower both scores. `zero_depth_check.py` tests that argument instead of resting on it, rescoring both states at the 150 m pad radius with the zeros recoded to NaN, six seeds and five 80/20 splits each, exactly as `radius_sweep.py` scores everything else:

| state | inflation, zeros as published | zeros recoded NaN | change |
|---|---|---|---|
| New Mexico | +0.0413 | +0.0449 | **+0.0035** |
| Ohio | +0.1222 | +0.1202 | **-0.0020** |

Recoding lowers *both* the random and the pad-grouped score in both states, which is what the structural argument predicts: a degraded column is seen by both partitions. It does not lower them by exactly the same amount, so the difference does move — upward in New Mexico, downward in Ohio — by about a thousandth of an R², against effects of 0.06 and 0.11. The argument is therefore supported in direction and in magnitude rather than exactly, which is what a test is for. `zero_depth_check.csv` carries the four rows and the underlying scores.

All are left as published, for the same reason and with the same caveat.

## Coordinates

All four states publish wellhead coordinates in decimal degrees on a WGS84-compatible datum, and the clustering in §3 uses them directly. Ohio stores both NAD27 and NAD83 pairs; `oh_build.py` prefers NAD83 and falls back to NAD27 where the NAD83 value is out of state bounds. Colorado additionally publishes `loc_qual`, which distinguishes a surveyed position from a planned one — the only per-well statement of coordinate quality any of the four agencies provides.
